# Skill: Planning and Task Breakdown

1. Read the approved specification and project context.
2. Identify the smallest end-to-end slice that delivers user value.
3. Split remaining work by behavior, not by file type; keep each task independently testable.
4. Record inputs, outputs, dependencies, acceptance criteria, risks, and out-of-scope items.
5. Order tasks by risk and dependency. Prefer proving uncertain integrations early.
6. Stop and ask when the spec lacks a decision that changes scope or architecture.

Every task must have a verification command or observable result. Do not create a plan that only lists files.
